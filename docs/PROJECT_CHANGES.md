# Glass Agent. Что изменилось с начала работы

Цель текущего MVP — провести маркетинговое поручение от сообщения в Telegram или VK до черновика, согласования и публикации на подключённой площадке. Компании используют отдельные знания и историю в PostgreSQL. Для запросов модели используется действующая подписка ChatGPT Plus через официальный Sign in with ChatGPT.

## Что было в исходном репозитории

В коммите `617b28f` уже были FastAPI, модели PostgreSQL/pgvector, миграции, Telegram-бот, парсеры и RAG, хранение истории, агент, шаблоны Pillow, публикация и планировщик. Подключение Plus, VK и отправка в настоящий канал тогда ещё не были подтверждены живой проверкой. [Исходный README](https://github.com/Saekikes42/glass_agent/blob/617b28fc8b6a6e4730746d2a7d1209a9775f423f/README.md)

## Что добавлено и исправлено

| Часть | Изменения |
| --- | --- |
| Подключение ChatGPT | Проверка ID-токена и разрешения на подписку, обработка ротации и отзыва токена, межпроцессная блокировка на Windows и Linux, шифрование и ограничение доступа к локальным файлам. CLI сообщает о таймауте входа и о результате отзыва. |
| Диалог и агент | Уточняющие вопросы используют тему предыдущего запроса для поиска. Ссылки в ответе и сохранённые ссылки используют общую нумерацию. Добавлены проверки границ времени, расхода модели и изоляции контекста компании. |
| База и повторный запуск | Сериализовано применение миграций. Хранение состояния синхронизации и прогресса индексации позволяет повторять загрузку без дублей. Сохранены роли, история, черновики, задачи и журнал действий. |
| Источники | Доработаны ограниченный обход сайта, Telegram Web и импорт JSON, инкрементальная загрузка стены VK. Для VK проверяется владелец записи до сохранения и обновления курсора. Добавлено восстановление курсора, затронутого более ранней загрузкой. |
| Личные сообщения VK | Добавлены привязка аккаунта VK к профилю в Glass Agent, проверка членства компании, выбор компании, диалог, отчёты, задачи и кнопки согласования. События Long Poll и позиция опроса хранятся в PostgreSQL. Повторно доставленные события отсеиваются по ID. |
| Дополнительный бот MAX | Добавлены личный диалог и согласование, доставка уведомлений и обработка вебхука с общей очередью PostgreSQL. Запуск предусмотрен отдельным профилем Compose. |
| Согласование и отправка | Одобрение связано с конкретной редакцией и выбранным каналом. Смена текста, изображения, площадки, канала или времени требует повторной проверки. При неопределённом результате отправки планировщик сохраняет состояние для ручной сверки. |
| Аналитика | Показатели публикации ищутся по компании, платформе, каналу и внешнему ID. Отчёт показывает доступные реакции и лайки даже при отсутствии просмотров. Средние просмотры считаются по предоставленным значениям. |
| Эксплуатация | Скорректированы запуск в PowerShell и Docker, диагностика, тесты, миграции и инструкции для оператора. Уведомления о согласованиях и задачах используют общий механизм доставки в Telegram и VK. |
| Права публикации VK | Добавлена диагностика для настроенной компании. Она запрашивает права ключа и доступ к целевой стене, показывает право работы с фото отдельной строкой. Семь новых автотестов используют тестовые ответы VK. |
| Исходные сообщения в Telegram | Агент получает текст или подпись пересланного сообщения и прямого ответа. При ссылке без доступного текста бот просит уточнить источник. Карточка нового черновика показывает его точный ID. |
| Очередь Telegram и сбои связи | При повторном нажатии бот сообщает текущий статус. Пост не ставится в очередь без канала назначения. При сетевом сбое до отправки запроса к ChatGPT выполняется ограниченный повтор, а прерванный поток возвращает понятную ошибку. |

Основная эксплуатация описана для Telegram и VK. MAX доступен как дополнительный профиль, который запускается отдельно.

## Что проверено на реальных сервисах

- **ChatGPT Plus.** Официальный вход выдал разрешение на использование подписки. Модель `gpt-6.1-sol` вернула ответ и сохранила контекст. Агент создал неопубликованный черновик с PNG из шаблона Pillow.
- **Сайт и публичный Telegram.** Загружены две страницы `salstek.ru` при ограниченном обходе и 16 постов `@salstek`. Поиск по материалам компании подтверждён запросами о продукте.
- **Закрытый Telegram.** Из экспорта Telegram Desktop импортированы 917 сообщений в 423 документах после объединения альбомов. Локальная модель создала 661 фрагмент индекса. Повторный импорт не добавил дублей. Запрос из другой компании не получил эти документы.
- **Стена VK.** Из ответа API сохранены 243 публикации нужной стены, для них построены 392 фрагмента индекса. Запись другого владельца пропущена. Повторная синхронизация прошла без новых записей, дублей и ошибок. Проверочный поиск вернул 6 результатов из VK в своей компании и 0 в другой.
- **Личный диалог VK.** Проверены запрет для непривязанного аккаунта, привязка, выбор компании, реальные ответы с источниками и уточнение после перезапуска. Два хода диалога записались с `is_mock=false`. После нажатия «Отклонить» тестовый пост перешёл в `rejected`. Попыток отправки было 0.
- **Сквозной сценарий Telegram.** В тестовую компанию «Студия Север» добавлен документ с вымышленным продуктом «Янтарный маяк» и его характеристикой — семь панелей. Модель E5 построила один фрагмент индекса. Пользователь отправил поручение в личный чат. ChatGPT `gpt-6.1-sol` взял факт из документа и подготовил черновик с PNG из шаблона Pillow. После кнопки «На доработку» и комментария бот прислал карточку редакции 3 с изображением. Кнопка «Согласовать и опубликовать» поставила материал в очередь. Штатный обработчик публикации запустили только для этого одобренного поста. Он отправил сообщение № 4 в тестовый канал GlassAITest с одной попытки, а бот прислал уведомление в личный чат. В ответ на уточнение без ID бот нашёл тот же пост, назвал семь панелей и сообщил статус `published`.
- **Фоновая задача.** Планировщик выполнил отчёт по таймеру и записал результат в PostgreSQL без входящего сообщения пользователя.
- **Анонс из архива.** Агент нашёл расписание шести волейбольных матчей в уже импортированном источнике и сослался на него. Бот Telegram собрал PNG для существующего черновика с помощью шаблона Pillow. Согласованная редакция текста с изображением опубликована одним сообщением в закрытом тестовом канале с первой попытки. Материал помечен как архивный.

Последний полный прогон на Windows — **166 тестов за 54,78 с**. Осталось 34 предупреждения об устаревших параметрах BeautifulSoup/lxml. Предыдущая версия прошла 157 тестов в Linux Docker. В автотестах внешние сервисы эмулируются. [Функции и ограничения](FEATURES_AND_LIMITS.md)

## Что остаётся для подключения

- Живая публикация на стене VK не подтверждена. При тестовой отправке VK вернул ошибку 15 на `wall.post` для использованного типа приложения. Для новой проверки нужны разрешённый тип приложения и права на целевую стену и фото.
- Для автоматического обновления закрытого Telegram-канала нужны `TG_API_ID`, `TG_API_HASH` и разрешённая сессия Telethon. Доступ к снимку истории уже проверен через экспорт Telegram Desktop.
- Для живого подключения MAX нужны верифицированный профиль организации, ИП или самозанятого и токен бота после модерации. В этой установке они отсутствуют. Личный диалог и публикация проверены с тестовыми транспортами, а обработчик вебхука — локально в Docker. [Условия создания бота MAX](https://dev.max.ru/help/chatbots) · [Развёртывание](DEPLOY.md)
- API и авторизация Telegram Mini App готовы. Интерфейс Vue 3 остаётся отдельной задачей. Для работы без включённого ноутбука предусмотрен запуск на собственной VM.

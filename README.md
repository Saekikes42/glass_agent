# Glass Agent

Glass Agent помогает команде готовить и согласовывать публикации в Telegram и VK. Бот отвечает на вопросы по материалам выбранной компании, указывает источники, готовит текст и изображение и отправляет черновик на проверку. Планировщик публикует согласованные материалы и запускает регулярные задачи. История, знания, роли, настройки и результаты хранятся в PostgreSQL с pgvector.

Для работы модели нужен Sign in with ChatGPT с разрешением на использование подписки ChatGPT Plus. `OPENAI_API_KEY` не используется. Для локальной разработки есть `AI_PROVIDER=mock_dev`, который помечает ответы как тестовые. MAX подключается отдельным профилем.

## Быстрый запуск

Установите Python 3.13 и запустите Docker Desktop. Выполните команды из корня репозитория в PowerShell.

```powershell
python -m venv .venv
$glassPython = ".\.venv\Scripts\python.exe"
& $glassPython -m pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d --wait db
& $glassPython -m scripts.manage init-db
& $glassPython -m scripts.doctor
```

1. В локальном `.env` задайте `TG_BOT_TOKEN` тестового бота и `ADMIN_TELEGRAM_IDS` администраторов. Оставьте `API_DEV_USER_ID` пустым и `SCHEDULER_IN_API=false`, если используете отдельный процесс планировщика.
2. Для VK включите сообщения сообщества и Bots Long Poll с событиями `message_new` и `message_event`. Задайте `VK_BOT_TOKEN` и `VK_BOT_GROUP_ID`. Эти настройки нужны для личных сообщений бота. Ключи чтения стен и публикации настраиваются отдельно. [Подключение VK](docs/VK_BOT_GUIDE.md)
3. Для работы с моделью выполните `& $glassPython -m scripts.chatgpt_login` на компьютере с браузером. Завершите вход в открывшемся окне OpenAI и проверьте `& $glassPython -m scripts.chatgpt_login --status`. [Условия использования подписки и подключение на VM](docs/CHATGPT_PLUS_OAUTH.md)

Запустите нужные процессы в отдельных терминалах из корня проекта. На один токен Telegram и на одно сообщество VK нужен один процесс опроса. Для новой установки используйте отдельную тестовую компанию и тестовые каналы.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.api.main:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m scripts.bot
.\.venv\Scripts\python.exe -m scripts.scheduler
.\.venv\Scripts\python.exe -m scripts.vk_bot
```

Проверка API доступна по адресу [127.0.0.1:8000/health](http://127.0.0.1:8000/health), Swagger — по [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Для постоянной работы предусмотрен Docker Compose на собственной VM. [Развёртывание и резервные копии](docs/DEPLOY.md)

Храните `.env`, `data/secrets/`, сессии Telethon, закрытые экспорты и резервные копии вне Git. Для закрытых материалов используйте локальный каталог файлов компании, который исключён из Git. Подключайте только те источники, на обработку которых у вас есть разрешение. Для общей установки проверьте доступ пользователей к каждой компании и правила использования её материалов в запросах к модели.

## Как показать работу

1. В личном чате Telegram-бота выполните `/start`, затем `/newcompany Демо`. Создание доступно администратору. Для уже созданной компании используйте `/companies` и `/use <slug>`.
2. Добавьте тестовый документ через API или подключите разрешённый источник и запустите `/sync`. Задайте вопрос по этому материалу и попросите указать источник. В Telegram также можно переслать пост с текстом или подписью и следом написать поручение. Другой вариант — отправить поручение ответом на исходное сообщение. [Источники и роли](docs/ADMIN_GUIDE.md) · [Руководство Telegram](docs/TELEGRAM_BOT_GUIDE.md)
3. Попросите бота подготовить пост, добавить PNG из шаблона и отправить его на согласование. Найдите карточку со статусом `pending_approval` через `/posts`. Кнопка «На доработку» переводит её в `revision` и принимает комментарий, кнопка «Отклонить» — в `rejected`. Правки текста, изображения, площадки, канала или предложенного времени требуют нового согласования.
4. Для живой отправки в Telegram назначьте компании тестовый канал командой `/setchannel telegram @test_channel` и дайте боту право писать в канал. На свежей карточке нажмите «Согласовать и опубликовать». Материал получит статус `scheduled`. При работающем планировщике проверьте публикацию в канале, уведомление и статус `published`. В VK для проверки диалога отправьте `/start` в личные сообщения сообщества, свяжите аккаунт с существующим пользователем и выберите компанию. [Сценарий демонстрации](docs/DEMO.md) · [Руководство VK](docs/VK_BOT_GUIDE.md)
5. Для просмотра отчёта используйте `/report`. Чтобы показать работу по расписанию, задайте ближайшее время тестовой задачи и дождитесь результата при работающем `scripts.scheduler`. Ручной запуск доступен командой `python -m scripts.manage run-task <slug> report`.

## Источники знаний

Поддерживаются сайт, публичное веб-превью Telegram, история через Telethon, новые записи собственного Telegram-канала через Bot API, импорт JSON из Telegram Desktop, стены VK и файлы PDF/DOCX/TXT/MD. Синхронизация и поиск работают по выбранной компании. Для VK потребуется ключ с доступом к чтению стены.

```powershell
& $glassPython -m scripts.manage add-source demo website https://salstek.ru/
& $glassPython -m scripts.manage add-source demo telegram_web https://t.me/salstek
& $glassPython -m scripts.manage sync demo
& $glassPython -m scripts.manage search demo "светопропускание Ultraview R"
```

Замените `demo` на код вашей компании и используйте нужные ей источники. Для закрытого Telegram экспортируйте историю из Telegram Desktop, сохраните `result.json` в закрытом локальном каталоге и добавьте источник `telegram_export` с путём к файлу. Такой источник отражает только содержимое экспорта. Для обновления подготовьте новый экспорт. Автоматический сбор закрытого канала в проверенной установке не включён. Для отдельной настройки получения истории через Telethon нужны `TG_API_ID`, `TG_API_HASH` и сессия аккаунта с доступом. [Настройка импорта и синхронизации](docs/ADMIN_GUIDE.md)

## Что проверено

| Возможность | Результат проверки |
| --- | --- |
| ChatGPT Plus и память | Официальный вход и реальные ответы. Уточнение без ID в Telegram нашло опубликованный пост. VK продолжил диалог по сохранённому контексту после перезапуска. Коннектор ограниченно повторяет запросы при ошибках подключения до получения ответа. При обрыве потока бот сообщает о временном сбое. |
| Telegram | Живой сценарий прошёл от поручения по тестовому документу через черновик с PNG из Pillow, возврат на доработку и согласование новой версии до публикации и уведомления. Отдельно проверена отправка согласованного поста с изображением по архивному материалу. |
| VK | Подтверждены чтение стены, личный диалог с ChatGPT, согласование и отклонение кнопками. Отклонённый материал не отправлялся. При отправке согласованного поста `wall.post` вернул ошибку 15 из-за типа приложения. Пост получил статус `failed` без внешнего ID. Для повторной проверки нужен пользовательский ключ с доступом к `wall.post` на целевой стене и к загрузке фото для публикаций с изображением. |
| MAX | Личный бот и публикация проверены с тестовыми транспортами. Локально проверен приём вебхука. Для живой проверки нужен подходящий бизнес-профиль и токен бота после модерации. |
| Знания и планировщик | Проверены импорт сайта, публичного Telegram, закрытого экспорта и стены VK, поиск по материалам, изоляция между компаниями и повторный импорт без дублей. Фоновый отчёт выполнился по расписанию и сохранился в PostgreSQL. |
| Mini App | Подготовлены REST API, проверка Telegram `initData` и OpenAPI. Пользовательский интерфейс Vue 3 остаётся отдельной задачей. |

Изображения в живых проверках созданы шаблонами Pillow. Для собственного развёртывания проверьте разрешённые условия доступа к ChatGPT Plus. [Функции и ограничения](docs/FEATURES_AND_LIMITS.md) · [История изменений и проверок](docs/PROJECT_CHANGES.md)

## Автотесты

Последний полный прогон на Windows прошёл успешно: **166 тестов**. Тесты используют тестовую модель и имитируют внешние API. Для тестов с PostgreSQL один раз создайте отдельную БД. Фикстуры пересоздают её таблицы, поэтому указывайте в `TEST_DATABASE_URL` только тестовую БД, если меняете адрес по умолчанию.

```powershell
docker compose exec db createdb -U glass glass_test
& $glassPython -m pytest -q
```
